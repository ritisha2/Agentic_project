ESP APM — PHASE 9
FRONTEND UI + BACKEND PRODUCT INTEGRATION ARCHITECTURE
Objective: bring the already-built Agentic backend into one usable product surface, validate FE↔BE contracts end-to-end, and prepare the platform for the later feedback/operational loop.
1. Executive Decision
Build the UI and FE↔BE integration layer before implementing the full feedback/learning loop. Treat the UI as the product integration surface that forces the existing Asset Context, Telemetry, KB, Objectives, Tools/Services, Events, LangGraph and Evidence Pack capabilities to work together.
Phase 9 should integrate and expose the existing backend. It should not rebuild those backend subsystems.

The key design principle is:
The Agent should return a structured visual explanation specification, not just text.
For example:
{
  "type": "trend_chart",
  "title": "Production decline — last 7 days",
  "x": "timestamp",
  "y": "liquid_rate_bpd",
  "series": ["actual"],
  "annotations": [
    {
      "timestamp": "...",
      "label": "degradation detected"
    }
  ],
  "evidence_ids": ["EV-12", "EV-19"]
}
The frontend then renders it.
That is much better than asking the LLM to generate arbitrary HTML/JavaScript.
Types of visual stories we should support
So yes: I would revise the Phase 9 architecture to explicitly include an XAI + Visual Storytelling subsystem inside the Agent Workspace.
