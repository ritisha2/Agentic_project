System PurposeThe ESP-PMM Agentic Assistant is an operational decision-support layer that sits above continuously-running ESP analytical services. It does not replace the Rule Engine, Anomaly Detection, Failure Prediction/RUL or Fault Classification models. It consumes their outputs, combines them with live/historical asset data and approved engineering knowledge, and uses an LLM to explain, investigate, recommend and document.The latest meeting adds that the models operate independently on a repeated schedule, persist current/historical deviations and predictions, and that the Agent must understand the system through objectives, tools, live data, model outputs and a knowledge base. fileciteturn3file0L3-L3The objective catalog supplied in the project lists 18 operational categories ranging from Current Status and Alarm/Event Analysis to Fault Diagnosis, Trend Analysis, Failure Risk, Troubleshooting, Maintenance, Data Quality, Procedures and Reporting. fileciteturn2file0L2-L182. What the Agent Does NOT DoIt does not retrain the LLM after every conversation.It does not continuously ingest every raw telemetry point into the prompt.It does not scrape the model team's dashboard.It does not scrape graph pixels from the frontend.It does not own the client/Advait asset registry.It does not replace the four ESP predictive models.It does not invent health, risk, fault, or RUL values.It does not use the KB as the authoritative source for live telemetry.It does not issue direct equipment-control commands in the current scope.19. Final Architecture RulesAdvait/client remains the source of truth for client asset identity/configuration.Simulator is the development telemetry source; abstract it behind a Telemetry Service.The AI-model team owns the four predictive models; the Agent consumes their outputs through an adapter.The Agent understands the system through objectives, tools, APIs, KB, runtime configuration and model semantics.The LLM is not the telemetry engine and is not trained during ordinary conversations.Knowledge Base contains stable/approved knowledge; dynamic facts come from runtime tools.Model outputs are authoritative outputs of the respective models, not recreated by the LLM.Dashboard and Agent use the same backend sources of truth.WebSocket/MQTT/Kafka are transport choices; the Agent sees logical tools/events.Evidence Pack bridges runtime/tools and LLM reasoning.Objective routing is controlled/hybrid; the LLM chooses only from registered objectives.What-if and operational control require engineering models/rules and explicit safety gates.Operator feedback should feed evaluation and future model/Agent improvement, not silently retrain the LLM online.23.
