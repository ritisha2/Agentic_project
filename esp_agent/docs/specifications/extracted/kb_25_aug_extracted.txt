Status and CoverageThe previous master Agentic architecture document contained the required KB concepts, but they were distributed across the overall architecture. This standalone document consolidates the complete KB subsystem. It covers the Lead guideline's Knowledge Categories, Hybrid Retrieval, Knowledge Authority Metadata and Structured Fault Objects, plus the implementation architecture needed to build them.The guideline explicitly requires fundamental ESP knowledge, OEM documentation, pump catalogues/performance curves, sizing/design, operating/commissioning, troubleshooting, reliability/run-life, well reports, workover/teardown/RCA and lessons learned/confirmed cases. Tenant / Client IsolationTenant-specific knowledge must be scoped server-side.Client SOPs and approved operating envelopes can outrank generic procedures within the tenant.Historical cases should normally be tenant/asset/equipment filtered before similarity ranking.Client asset hierarchy/tag mapping is not generic RAG truth; use the Asset Context Service as the runtime source of truth.Unauthorized tenant documents must never enter the retrieved evidence set.15. Final RulesVector-only RAG is not acceptable for the required ESP use cases.Structured fault objects are mandatory alongside source documents.Historical cases must retain confirmed cause, action and outcome.Numeric pump curves and limits require exact/structured retrieval and source traceability.Authority is an evidence policy; it is not just a ranking score.Client-specific KB is tenant-scoped.Current asset hierarchy/configuration should remain sourced from the Asset Context Service.Knowledge retrieval must return source, revision, authority and applicability metadata.Retrieved documents are untrusted data with respect to Agent instructions.KB releases require versioning, approval, rollback and retrieval benchmarks.23.
